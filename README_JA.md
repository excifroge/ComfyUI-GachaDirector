# Gacha Director

**MiniMax H3 のディレクターコンソール。** ComfyUI カスタムノードです。キャンバス上の 1 ノードからタブ式パネルを開き、テキストからの動画生成、画像からの動画生成、先頭・最終フレーム、複数キーフレーム、動画の続きの生成、参照生成、動画編集を同じパネルで行えます。

名前の Gacha はゲームのガチャのことで、一度に N 本のテイクを生成し、ショットごとに 1 本を選んで最終クリップに合成する流れは、10 連ガチャのようなものです。

## 解決する課題

MiniMax H3 の公式テンプレートは、用途ごとに異なるノードグラフになっています。用途を変えるたびにグラフを切り替える必要があり、複数のシードを比較したり、設定ごとの所要時間を調べたり、2 本の結果からそれぞれ一部を取り出したりするには、自分で組む必要があります。

Gacha Director はこれらを 1 ノードにまとめ、次の 5 点を中心に構成しています。

- **タブ式の作業パネル。** 編集ソフトのように、作業の流れに沿ってページを分けています：プロジェクト → 編集 → 生成 → 仕上げ → 出力。
- **ショットごとに素材を整理。** 各ショットのカードに、その中で起きることと、使う画像・動画・音をまとめます。素材の番号付けとモデルへの宣言は生成時に自動で行われるため、プロンプトに手書きする必要はありません。
- **所要時間を記録する実行プリセット。** プリセットは「今回どれだけのコストをかけるか」に名前を付けたものです。`Draft`（下書き）、`Standard`（標準）、`Final`（完成版）の 3 つを内蔵しています。各プリセットは実測の所要時間を、クリップの長さごとに記録します。
- **テイク → 採用 → 最終クリップ。** クリップ全体のテイクを N 本まとめてキューに追加し、ショットごとに 1 本を採用してから「合成」で最終クリップを出力します。全ショットで同じテイクを使えば、そのテイクをそのまま出力します。カットの位置でテイクを切り替える場合はそのまま編集でつなぎ、生成し直しません。同じ長回しの途中で切り替える場合は、つなぎ目だけを描き直します。
- **カットか長回しかは自分で指定。** 別のショットに切り替えるのか、同じショットを続けるのかを編集ページで設定します。モデルへの指示も、完成クリップのつなぎ方も、その設定に従います。カットで音声も映像と一緒に切り替えるか、カット前のテイクの音声を続けるかも、同じ場所で個別に設定します。

パネルでは分かりやすい言葉を使います。解像度は幅 × 高さ、長さは秒、画像は「このショットの最初のフレーム」です。モデルが必要とするラベル、宣言、画素数、スケジュールで変化する denoise は、パネル側で計算します。

ノード自体はサンプリング処理を再実装しません。実行時に ComfyUI の標準ノード群へ展開し、標準のコンディショニングノード、サンプラー、VAE が実際の処理を行います。

## 対応する使い方

H3 の各種「モード」は、いくつかの仕組みの組み合わせです。Gacha Director ではモードを選ぶ代わりに、ショットに素材を入れてそれぞれの**使い方**を選びます。用途は素材によって決まります。ショットカードの読み取り専用タグ（「テキストから生成」「先頭・最終フレーム」「参照から生成」など）で、現在の素材がどの用途になるかを確認できます。

| 追加するもの（素材・使い方） | 用途 | モデル | 展開される標準ノード |
|---|---|---|---|
| テキストのみ | テキストからの動画生成 | fl2va | `MiniMaxH3ImageToVideo` |
| 最初のショットの画像・「先頭フレーム」 | 画像からの動画生成 | fl2va | 同上。`first_frame` に接続 |
| 最後のショットの画像も追加・「最終フレーム」 | 先頭・最終フレームからの生成 | fl2va | 同上。`first_frame` / `last_frame` に接続 |
| 最終フレームのみ | 最終フレームからの生成 | fl2va | 同上。`last_frame` に接続 |
| 画像・「中間フレーム」、または途中のショットの先頭・最終フレーム | 複数キーフレーム | どちらも可 | `MiniMaxH3AddGuide` を直列に接続 |
| 動画・「動画の続き」 | 続きの生成 | どちらも可 | `MiniMaxH3AddGuide` |
| 画像・「対象の参照」 | 参照生成 | ref2va | `MiniMaxH3ReferenceToVideo` |
| 動画・「動作・カメラ参照」、音・「登場人物の声」「音声参照」 | 動き、カメラワーク、声質、BGM の参照 | ref2va | 同上 |
| 音・「ショット内の原音」 | 音声をそのまま完成クリップに入れる | どちらも可 | `MiniMaxH3AddGuide` |
| ショットの説明で単独の行に書くセリフ（`@名前 says: …`） | セリフ：キャラクターがこの言葉を話す | どちらも可 | ノードは追加せず、セリフをプロンプトに記述 |
| ソース動画・「動画編集」 | 動画編集（公式の方法） | ref2va | 同上。ソース動画は `<Video 1>` |
| ソース動画・「動画の続き」 | この参照区間の末尾から続きを生成 | ref2va | 同上 |
| ソース動画・「ソース再描画」 | 低い強さで再描画 / 一部だけ再描画 | どちらも可 | `VAEEncode` + `LTXVConcatAVLatent`。一部だけ再描画する場合は `SetLatentNoiseMask` も追加 |

これらは組み合わせられます。たとえば「ソース動画を編集し、対象と最終フレームの画像を追加する」という構成も使えます。

編集ページの「クリップ」にある「開始方法」に続くボタンは、これらの組み合わせへのショートカットです。押すと既存の素材がその用途に必要な素材に置き換わり、プロンプトは残ります（置き換えられた素材への @ 参照は、通常の名前のテキストになります）。クリップの長さとアスペクト比も残りますが、「動画編集」だけはソース動画のアスペクト比に合わせ、ソースに収まる最長の有効な長さに変更します（最大 362 フレーム）。たとえば 120 フレームのソースでは 107 フレームとなり、残りの 13 フレームは使われません。タイムライン上部に残りのフレーム数が表示されます。全区間を使うには長さを 124 に変更します。その影響は[編集ページ](#編集ページ)のソース動画の項を参照してください。操作は取り消せます。

### サンプル動画

各行は、用途ごとに `Standard` プリセット（標準モデル、20 ステップ、864×480）で生成した 1 本の完成クリップから、等間隔に 6 フレームを抜き出したものです。シードはすべて 7 です。各用途で実行したのはこの 1 回だけで、結果を選別していません。

同じ 6 本を並べて再生したものです（12 fps に間引いています）。

## インストール

ComfyUI **0.39 以降**が必要です（`MiniMaxH3AddGuide`、H3 のノイズマスク、`LTXVConcatAVLatent` の H3 対応を使用します）。

1. このリポジトリを `ComfyUI/custom_nodes/ComfyUI-GachaDirector` に配置します。
   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/excifroge/ComfyUI-GachaDirector
   ```
2. ComfyUI を再起動します。ログに `Gacha Director v2.1.0: 10 nodes registered` と表示されれば、インストール完了です。

追加の pip 依存関係はなく、他のカスタムノードパッケージにも依存しません。モデルファイルは [ComfyUI の公式チュートリアル](https://docs.comfy.org/tutorials/video/minimax/minimax-h3)に従って用意してください。顔のリファインを初めて使う際は、ComfyUI に付属する kornia が約 400 KB の顔検出用の重みを自動でダウンロードします。

## クイックスタート

`example_workflows/` には、ノードと接続が同じで、接続するモデルが異なるワークフローが 2 つあり、それぞれに最初に試すためのプロンプトが入っています。

| ワークフロー | モデル | 用途 |
|---|---|---|
| `GachaDirector_Base.json` | fl2va | テキストからの動画生成、画像からの動画生成、先頭・最終フレーム、複数キーフレーム、続きの生成 |
| `GachaDirector_Reference.json` | ref2va | 参照生成、動画編集、複数キーフレーム、続きの生成 |

どちらかを開き、4 つのローダーと高速化 LoRA のローダーに自分のモデルファイルを指定して、次の手順を進めます。

1. ノードの **Gacha Director を開く**をクリックします。
2. **編集**ページでショットごとに起きることを書きます。素材はカード右側の「+ 画像 / + 動画 / + 音」、または「クリップ」の「開始方法」に続くボタンから追加します。
3. **プロジェクト**ページでプリセットを選びます（`Draft` / `Standard` / `Final`）。そのプリセットの画面サイズと所要時間が表示されます。
4. **生成**ページの「N テイク生成」をクリックするか（N はプロジェクトページの「テイク数」で設定）、ComfyUI 自体の実行ボタンで 1 本を生成します。

> [!IMPORTANT]
> `Draft` プリセットは高速モデル、つまりノードの `model_turbo` 入力を使います。サンプルワークフローでは、高速化 LoRA を適用したモデルが接続済みです。その LoRA がない場合は、LoRA のローダーノードを削除し（`model_turbo` は未接続にする）、`Draft` を選ばないか、`Draft` のモデルを「標準モデル」に変更してください。

### 一通りの例：実写映像を雪景色に変える

ソース動画は、オープンムービー『Tears of Steel』で橋の上の 2 人が会話する、124 フレームの実写映像です。人物、動作、カメラワークを保ち、季節を雪の降る冬に変えます。

1. `GachaDirector_Reference.json` を開き、ノードの **Gacha Director を開く**をクリックします。
2. **編集**ページの「クリップ」で、「開始方法」に続く「動画編集」をクリックし、ソース動画を選びます。クリップの長さは 124 フレームになり、アスペクト比はソースに合います。「ソース用途」は既定で「動画編集」になり、「ソース再描画」はオフです。そのままで構いません。
3. 4 か所にテキストを入力します。変更したい内容はショットに、残したい内容はソース動画の「保持・変更内容」に書きます。

   | 入力箇所 | 内容 |
   |---|---|
   | 全体の説明 | `The target video is live-action film footage in heavy snowfall.` |
   | ショット内容 | `The scene of <Video 1> now takes place in deep winter: thick snow is falling, the trees are bare and white, snow lies on the bridge railing, the street and the rooftops, and the light is cold and blue. The two people, their clothes, their movements and the camera are the same as in <Video 1>.` |
   | ソース動画の「詳細設定」にある「保持・変更内容」 | `the people, their motion and timing, the camera and the composition of <Video 1> are kept; only the season and the weather change` |
   | 環境音 | `Muffled winter air, soft wind, snow hissing on stone.` |

   編集するソース動画はプロンプト内で `<Video 1>` になるため、そのまま書けます。「概要」は空欄で構いません。生成の種類と「生成する動画は `<Video 1>` の編集版」という冒頭文が自動で加わります。
4. 「最終プロンプト」をクリックすると、実際にモデルへ送るテキストを確認できます。

   ```text
   subject_definitions:
   <Video 1> is the source video for the target video edit.

   summary: [video editing] The target video is an edited version of <Video 1>.

   retention_analysis:
   <Video 1> (motion and camera work): fully_preserved - the people, their motion and timing, the camera and the composition of <Video 1> are kept; only the season and the weather change.

   detailed_description: The target video is live-action film footage in heavy snowfall. [Shot 1] The scene of <Video 1> now takes place in deep winter: thick snow is falling, the trees are bare and white, snow lies on the bridge railing, the street and the rooftops, and the light is cold and blue. The two people, their clothes, their movements and the camera are the same as in <Video 1>.

   overall_soundscape: Muffled winter air, soft wind, snow hissing on stone.

   non_diegetic_music: N/A
   ```

5. **プロジェクト**ページでまず `Draft` を選んで方向性を確認します（4 ステップ、約 2.5 分）。問題なければ `Standard` に切り替えます（20 ステップ、864×480、約 12.5 分）。所要時間は VRAM 24 GB の GPU 1 枚で測定したものです。

## ノード

![キャンバス上のノードとローダー](docs/ja/node.jpg)

**入力**

| 名前 | 型 | 説明 |
|---|---|---|
| `model` | MODEL | H3 の拡散モデル。参照モデルには ref2va、ベースモデルには fl2va を接続します。 |
| `clip` | CLIP | `CLIPLoader` で種類を `minimax` にします。 |
| `vae` | VAE | H3 の動画 VAE。 |
| `audio_vae` | VAE | H3 の音声 VAE。 |
| `model_turbo` | MODEL、省略可 | 同じモデルに高速化 LoRA を適用したもの、または蒸留モデルです。プリセットのモデルが「高速モデル（turbo）」のときに使います。 |
| `sampler` | SAMPLER、省略可 | 接続すると、プリセットのサンプラーを上書きします。 |
| `sigmas` | SIGMAS、省略可 | 接続すると、プリセットのスケジューラーとステップ数を上書きします。 |

ノード上には、プリセット選択、`seed`（ComfyUI 標準の「生成後の制御」を含む）、読み取り専用の数値表示（画面サイズ、フレーム数、ステップ数、そのクリップ長でのプリセットの実測所要時間）、パネルを開くボタン（横に UI 言語の切り替え）の 4 つだけがあります。それ以外はすべてパネル内で設定します。

**出力**：`frames`、`audio`、`fps`、`frame_count`、`source_frames`、`latent`、`positive`、`model`、`prompt`（実際にモデルへ送るプロンプト）、`run_report`（今回の実行の概要）。

## パネル

ページに表示するのは名前と値だけです。各パラメーターの説明はツールチップにまとめています。パラメーター、ボタン、見出しにマウスを重ねて半秒待つと表示されます。

### プロジェクトページ

![プロジェクトページ：左にプリセット、右上に解像度・フレームレート・長さ・所要時間の目安](docs/ja/project.jpg)

左にプリセット一覧があり、各項目に現在のクリップでの画面サイズ、ステップ数、モデルが表示されます。右には選択中のプリセットがあり、上部の 4 つの数値は**解像度**（幅 × 高さ）、**フレームレート**（24 fps、モデル固定）、**長さ**、**所要時間の目安**（この長さでの実測平均）です。

| 設定 | 説明 |
|---|---|
| 解像度 | サイズの選択肢を、現在のクリップのアスペクト比での幅 × 高さとして表示します。プリセットが保存するのは幅と高さではなく画素数です。アスペクト比はクリップに属するため、同じプリセットを横長にも縦長にも使えます。「標準（公式テンプレート）」は公式テンプレートのサイズ（16:9 では 864×480）、「ネイティブ（学習時の解像度）」は学習時のサイズ（1344×768）です。 |
| 解像度・「カスタム…」 | 正方形にしたい場合など、幅と高さを直接入力します。モデルは 32 の倍数しか扱えないため、それ以外では実際に使う最も近いサイズが表示されます（720 × 720 は 736 × 736）。幅または高さが 256〜2048 ピクセルの範囲外なら赤字で表示され、適用できません。カスタムの幅と高さに合わせて、クリップのアスペクト比も変わります。その後で一覧の別のサイズを選んでも、比率は変わりません。 |
| ステップ数 | 公式の既定値は 20。高速モデルでは 4 または 8 にします。 |
| モデル | 「標準モデル」、または「高速モデル（turbo）」（ノードの `model_turbo` 入力）。 |
| テイク数 | 生成ページのボタン 1 回で、何本をキューに追加するか。 |
| 参照素材サイズ | 参照動画をどこまで縮小するか、参照画像を縮小するかの設定です。参照モデルの速度にだけ影響し、完成クリップの解像度は変わりません。参照動画はすべてのステップで計算に加わるため、動画参照を使う場合は速度に最も影響します。 |
| 詳細 | 画素数（MP）、ガイダンスの強さ（CFG）、サンプラー、スケジューラー、スケジュールのシフト · 映像 / スケジュールのシフト · 音声（既定値 12 / 3）、VRAM の節約。公式の既定値は CFG 1、`res_multistep` / `simple`。 |

その下にはプリセットの所要時間の記録があります。テイクの所要時間は**キューに追加した時点**のプリセットとクリップ長に記録されます（待機中にページを再読み込みした場合は実行開始時点のものを使います）。ComfyUI 自体の実行ボタンで開始した場合は**実行開始時点**のものを使います。実行中にプリセットのパラメーターを変えた場合、その実行は記録しません。パラメーターを変えると、以前の記録は既定で自動消去されます。その設定を表さなくなるためです。記録するのはこのノード自身が動いていた時間だけで、ローダーがモデルをディスクから読む時間、後ろに接続されたノード、同じワークフロー内の別のディレクターノードは含みません。合成と顔のリファインは計測しません。クリップの生成とは別の処理であり（同じクリップ・同じプリセットでの実測では合成が約 128 秒、テイクが約 100 秒）、記録するとプリセットの所要時間がずれるためです。

> [!NOTE]
> `Draft` と `Final` は同じクリップにはなりません。画面サイズを変えるとノイズも変わり、同じシードでも結果が異なります。`Draft` は「プロンプトと素材の方向性が合っているか」を判断するためのもので、シード選びのためのものではありません。

### 編集ページ

![編集ページ上部：プレビュー、タイムライン、クリップ設定](docs/ja/edit-timeline.jpg)

上部にプレビュー、タイムライン、再生コントロールがあります。タイムライン上の行にはクリップの長さ（秒・フレーム数・フレームレート）、画面サイズ、ステップ数、ショット数、現在の素材から決まる生成の種類を表示します。その下はクリップ、共通素材、ショットの順です。

**クリップ**

- **モデル**：参照モデル（ref2va）またはベースモデル（fl2va）。参照モデルは人物・動画・音を参照素材として受け取ります。ベースモデルのコンディショニング入力はテキストとクリップ全体の先頭・最終フレームだけです。フレームに固定するもの（途中の画像、「動画の続き」の動画、そのまま入れる音）は別途追加され、どちらのモデルでも使えます。素材とモデルが合わない場合は、ページに理由が表示されます。
- **長さ**：5 / 10 / 15 秒のボタンを押すか、秒数を直接入力します。モデルが扱える長さに自動で合わせます（入力した値から少し変わることがあり、横に対応するフレーム数を表示します）。標準ノードが示す学習範囲はおよそ 5〜15 秒（124〜362 フレーム）です。より長い値も入力できますが、学習した範囲を超えます。
- **アスペクト比**：「ソースの比率」、または比率を指定します。

![編集ページの共通素材：全体の説明、環境音、すべてのショットで使える画像・動画・音](docs/ja/edit-shared.jpg)

**共通素材**：どのショットでも使うものをここに置きます。左には全体の説明（クリップ全体のスタイルとシーン）、環境音、BGM、概要、右には共通の画像・参照動画・音があります。ソース動画は最下部です。1 ショットにしか出ない素材は、そのショットのカードに入れます。参照モデルの上限は、クリップ全体で画像 9 枚、動画 3 本、音声 3 本、合計 12 ファイルです。このセクションの上部に使用数が表示されます。

**ショット**：クリップをいくつかの区間に分け、それぞれをカードで表示します。左にそのショットで起きることを書き、右にそのショット用の画像・動画・音を入れます。プロンプトの `[Shot 1]`、`[Shot 2] At 00:02.833, …` に対応し、別々に生成するわけではありません。説明も、そのショット用の対象や参照素材もないショットはプロンプトに含まれず、含まれたものだけで番号を振ります。カードの左にはショットの長さに比例して区切ったナビゲーターがあり、クリックするとそのショットへ移動します。

各素材には、サムネイル、名前、**使い方**があります。使い方によってモデルにとっての意味が決まります。

| 素材 | 使い方 | 意味 |
|---|---|---|
| 画像 | 対象の参照 | 画像の人物や物が映像に登場します。見た目の参照で、特定のフレームには固定しません。画像のある対象は参照モデルに見せます。ベースモデルには参照画像用の入力がなく、説明文だけを使います。 |
| | 先頭フレーム / 最終フレーム | ショットがこの画像から始まる / この画像で終わります。 |
| | 中間フレーム | ショット内で指定したフレームがこの画像になります。 |
| | 絵コンテ（構図参照） | 構図をモデルに見せるだけで、フレームは固定しません（参照モデル）。 |
| 動画 | 動作・カメラ参照 | この動画の動きとカメラワークを参照します（参照モデル）。 |
| | 動画の続き | 動画の短い区間（5 / 22 / 39… フレーム、音声付きも可）をショットの先頭に固定し、モデルがその続きを生成します。最初のショットに置くと、続きの生成になります。 |
| 音 | 登場人物の声 | 選んだ対象がこの声で話します（参照モデル）。 |
| | 音声参照 | 音色や曲調を参照します（参照モデル）。 |
| | ショット内の原音 | この音がショットの先頭からそのまま完成クリップに入ります。 |

素材行の右の小さな三角は「詳細設定」です。対象の種類、説明、短い呼び名、複数の画像、保持の度合い（「完全保持」「一部変更可」「特徴の転用」「弱い参照」）、動画のどの区間を使うかなどを設定します。

**素材ライブラリ。** 上部バー右側の「素材ライブラリ」で、どのページからでもフローティングウィンドウを開けます。移動・サイズ変更ができ、ページを切り替えても同じ位置に残ります。位置とサイズはブラウザーに保存されます。

![素材ライブラリ：取り込みと生成の 2 分類、種類の絞り込み、自作のフォルダー。素材はショットの素材欄へドラッグできる](docs/ja/library.jpg)

- **2 つの分類**：*取り込み*には ComfyUI の `input` フォルダー内のファイル、*生成*には `output` 内の生成済みファイルが新しい順に並びます。どちらも「画像」「動画」「音声」で絞り込み、ファイル名で検索できます。
- **フォルダー**：左側にフォルダーやサブフォルダーを作れます。ダブルクリックで名前を変更し、素材をフォルダーへドラッグして分類します。「未分類」へドラッグすると分類を外せます。素材ライブラリ内だけの仮想フォルダーなので、ディスク上のファイルは移動も名前変更もせず、ほかのワークフローからも引き続き参照できます。分類は ComfyUI のユーザーデータに保存され、全ワークフローで共有します。
- **素材を使う**：ウィンドウからショットカードの素材欄（そのショットに追加）か共通素材欄（全ショットで共有）へドラッグします。Ctrl または Shift を押して複数選択し、まとめてドラッグすることもできます。「+ 画像」「+ 動画」「+ 音」でも同じウィンドウが開き、使える種類だけが表示されます。この場合は素材をクリックすると追加されます。
- **PC からの取り込み**：「PC から取り込む…」をクリックするか、ウィンドウへファイルをドロップします。取り込んだ素材は開いているフォルダーに分類されます。ショットの素材欄、共通素材欄、ソース動画欄へ直接ドロップすることもできます（ソース動画欄ではドロップした動画がソースになります）。ファイルは ComfyUI 標準のアップロードと同じ経路で `input` にコピーされ、同名ファイルがある場合は ComfyUI が新しいファイルの名前を変更します。パネル内のほかの場所にドロップしても何も起きず、背後の ComfyUI キャンバスにも渡りません。

「動画の続き」の素材ライブラリでは、生成済みの完成クリップも選べるため、前の結果を直接続きの生成に使えます。「動画の続き」レシピは、選んだ動画の末尾 22 フレームを最初のショットの先頭に置きます。新しいクリップの先頭 22 フレームが前のクリップの末尾に固定されるため（ごく近い映像ですが、ピクセル単位では同一ではありません）、124 フレームのクリップで新しく生成する内容は 102 フレーム（4.25 秒）です。つなぐ際は重複する 22 フレームを切り取ります。

![プロンプトで @ を入力すると、名前で指定できる素材が表示される](docs/ja/edit-mention.jpg)

**モンタージュか長回しか：映像と音声に個別のリンク。** ショットカードの間にある 2 つのチェーンアイコンで、下のショットを上のショットにどうつなぐかを指定します。左が映像、右が音声です。リンクがつながっていると明るく、外れていると暗く表示され、クリックで切り替えます。

映像：

- *リンクなし = カット（モンタージュ）*：別のショットに切り替えます。プロンプトでは新しい `[Shot N] At <時刻>` の区間になります。
- *リンクあり = 連続（長回し）*：カットせず同じショットを続けます。区間を分けるのは、内容の記述とテイクの採用を別々に行うためです。プロンプトでは連続する区間を 1 つの `[Shot]` にし、各区間の説明を順に 1 段落へまとめます（セリフは単独の行のまま）。公式のプロンプト形式にはカットの時刻しかなく、ショット内の出来事を秒数で指定する書式はありません。そのため、長回し内の順序は文章の順で決まり、具体的な時刻はモデルが決めます。

音声（カットの位置でのみ意味を持ちます）：

- *リンクなし = 映像と同時に切り替え*：カット後は、新しい映像に採用したテイクの音声を使います。これが既定です。
- *リンクあり = 継続*：カット後もカット前のテイクの音声を使い続け、映像だけが別のテイクに切り替わります。複数のカットで続けてリンクすると、最初のテイクの音声が続きます。
- 映像がつながっている場合（長回し）、音声は必ず映像とともに連続します。音声リンクはつながった状態でロックされます。

音声リンクは生成には影響しません。各テイクは、これまでどおりクリップ全体の映像と音声を含みます。リンクが決めるのは、最終クリップの各フレームでどのテイクの音声を使うかだけなので、カットの両側で**異なる**テイクを採用した場合にだけ違いが聞こえます。映像のカット位置も変わりません。

新しく挿入した境界は、ゼロから生成するクリップでは既定でカット、ソース動画のあるクリップでは連続になります（ソースはそこでつながっているため）。タイムラインではカットが塗りつぶしたひし形、長回し内の区切りが白抜きのひし形と横線です。左のナビゲーターでは、前の区間を続けるショットとの境界が破線になります。

以前のワークフローにはこの 2 つの設定がありません。開いたときには、ソース動画のあるクリップの各ショットは長回しとして扱い（こうしたクリップは以前からつなぎ目を生成し直してテイクをつないでいたので、動作は変わりません）、ゼロから生成するクリップの各ショットはカットとして扱います。音声は以前と同じく、すべて映像と一緒に切り替えます。

![編集ページのショットカードの間にある 2 つのリンク：左が映像、右が音声](docs/ja/edit-join.jpg)

**番号の手書きは不要。** 素材の番号（`<Subject 1>`、`<Picture 2>`、`<Video 1>`…）と「この画像は何番目のショットの先頭フレーム」といった宣言は、生成時に自動で付けます。誰が何をするかを指定するには、プロンプトで `@` を入力して一覧から名前を選びます（そのショット用の素材が先に並び、上下キーと Enter でも選べます）。素材行の `@` ボタンで、カーソル位置に名前を挿入することもできます。名前や使い方を変えたり、素材を外したりすると、プロンプトにも反映されます。ショットに属していて説明で名前を指定していない対象・参照動画・音の参照には、「このショットに登場する」などの文を自動で補います。先頭・最終フレームの画像は専用の宣言があり、登場人物の声は対象と一緒に宣言します。「最終プロンプト」で全文を確認でき、内容を変えると自動更新されます。

フレームに固定した素材はショットに追従します。境界をドラッグしても、「先頭フレーム」はそのショットの先頭のままです。境界を挿入・削除した場合は、素材が元のフレームに残ります。タイムラインのマーカーは表示専用です。

**ソース動画**（任意、共通素材の最下部）：クリップ全体の素材となる映像です。入力ディレクトリから選ぶか、生成済みの完成クリップを選べます。「ソース用途」には 4 つの選択肢があります。

- *動画編集*（参照モデル、既定）：公式の動画編集方法で、モデルには `<Video 1>` として渡します。
- *動画の続き* / *動作・カメラ参照*：同じく `<Video 1>` として渡しますが、役割が異なります。渡すのはソース動画の開始フレームから、クリップと同じ長さの区間です。別の位置から続ける場合は「詳細設定」で開始フレームを変えます。
- *ソース再描画*：開始時の映像としてだけ使います。

「詳細設定」内の「ソース再描画」（ベースモデルは参照用の入力がないため、ソース動画を選ぶとこの使い方だけになります）：ゼロからではなく、元動画にノイズを加えて描き直します。「変更量」の横には、計算した開始時のノイズの割合が表示されます（[実測データ](#実測データ)を参照）。元の構図を残すには、この率が 100% を十分に下回る必要があります。一部だけ描き直す場合に必要です。

開始フレーム以降のソース動画がクリップより短い場合、不足分は最後のフレームで止まり、生成結果の末尾も動きが止まります（実測では、4 フレーム不足すると、最後の約 6 フレームで徐々に動きが止まりました）。

> [!NOTE]
> 動画編集に「ソース再描画」は必要ありません。実測では、ソース動画を編集用に参照するだけで、ゼロから生成しても構図・動き・カメラワークが元動画に追従しました。さらに元の画面から描き直しても（変更量 0.85）、ほぼ同じクリップになり、時間だけが長くなりました。

**部分再描画**（「ソース再描画」が有効な場合だけ表示）：再生成する[セル](#時間セル)を選び、それ以外は元のまま残します。ソースに音声トラックがある場合は、残すセルの音も保持されます。

**セリフ**：H3 は映像と音声を同時に生成するため、キャラクターに話させられます。ショットの説明では、セリフを単独の行に書きます。

```text
@girl pulls down her scarf and looks straight at the camera.
@girl says quietly: I have been looking for you.
```

`@girl` は girl という名前の対象で、画像の有無は問いません。対象に属さない声は `@voice(a warm elderly male voice) says cheerfully: Good morning!` と書きます。コロンの前が話し方、後が実際に話す言葉です。既定は英語で、他の言語では `@girl` または `@voice(…)` の直後に `[Japanese]` などのタグを付けます。モデルへ送る際は公式ガイドの形式、`<Subject 1> (S1) says quietly, <d>[English] I have been looking for you.</d>` になります（対象に画像がある場合は `<Subject 1>`、テキストだけの場合はその説明または短い呼び名）。同じ話者の `(S1)` はショットをまたいでも変わりません。`@girl says "…"`（コロンなし）はセリフとして扱われず、「最終プロンプト」に案内が表示されます。特定の声で話させるには、音声を追加し、使い方を「登場人物の声」にして対象を選びます。その音声が声質の参照になり、話す言葉はプロンプトに従います。

**詳細**（ページ最下部、折りたたみ）：

- *プロンプト形式*：「構造化（公式の構成）」（公式形式で組み立てます。[プロンプトの組み立て方](#プロンプトの組み立て方)を参照）、または「自由記述」（入力したまま送ります。LoRA のトリガーワードや手書きの完全なプロンプト向けで、各ショットの説明は送らず、素材名も置き換えません）。
- *ネガティブプロンプト*：プリセットのガイダンスの強さ（CFG）が 1 以外の場合だけ使われます。公式テンプレートはすべて CFG 1 で、ネガティブ側の分岐はありません。

### 生成ページ

![生成ページ：最上部にシーケンスプレビュー、その下に生成ボタン、最終クリップ、最初のショットのテイク一覧](docs/ja/generate.jpg)

![生成ページ：ショットごとにテイクを採用。カードサイズは個別に調整でき、左のナビゲーターはショット長に比例して区切られる](docs/ja/generate-shots.jpg)

最上部の**シーケンスプレビュー**では、現在の採用内容に従って、各ショットの区間を順に再生します。モデルは使いません。テイク未採用のショットは「ショット N · 未採用」と表示し、その長さの間は空白になります。長回し内でテイクを切り替えた位置はプレビューではハードカットになり、つなぎ目の映像は合成時に生成します。最終クリップがある場合（「合成」を実行し、その後に採用内容とつなぎ目の設定が変わっていない場合）は、それ自体を再生します。下のタイムラインと連動し、再生中は赤い再生ヘッドが追従します。目盛りをドラッグするとプレビューもその位置へ移動し、ショットをクリックすると該当ショットのテイクへスクロールします。音声は既定でオフです。再生バーの ♪ が音声スイッチで、パネル内の全プレーヤーで共通です。オンにすると、プレビューの各区間はその区間が属するテイクの音声を再生します。

![生成ページのタイムライン下の範囲帯：長回し内でテイクを切り替えた位置に、再生成範囲を示す両端をドラッグできるバーがある](docs/ja/generate-seam.jpg)

**つなぎ目の再生成範囲。** 長回し内の前後の区間で異なるテイクを採用すると、タイムラインの下に帯が現れ、つなぎ目の位置にバーが表示されます。合成時に再生成するのはこの範囲で、それ以外の映像は採用したテイクを使います。

- 既定は**自動**です。つなぎ目の少し前から、つなぎ目があるセルの末尾までを再生成します。目標は少なくとも 12 フレームで、実際はセル内のつなぎ目の位置に応じて 12〜21 フレームになります。つなぎ目がセル境界上にある場合は、その前の 12 フレームだけを描き直し、後ろのテイクは 1 フレームも描き直しません。クリップの先頭や長回しの端に近い場合は短くなります。セル境界で終える理由は[時間セル](#時間セル)を参照してください。
- バーの両端をドラッグして範囲を指定できます。両端は帯の細い線、latent フレームの境界にスナップします。1 セルに 5 本あり、間隔は 1 フレームと 4 フレームずつ 4 区間です。長い線はセル境界です。バーの横に、つなぎ目の前後でそれぞれ何フレームを再生成するかが表示されます。
- バーが橙色になるのは、安定しにくい範囲です。12 フレーム未満、または右端がセル境界以外の場合で、直後の保持フレーム 1–2 枚に測定できる変化が出ることがあります。橙色は注意表示で、合成は可能です。
- バーをダブルクリックすると自動範囲に戻ります。範囲は長回しの外へ出ません。端で短くなった場合はツールチップに説明が表示されます。
- 横の「テイク間の一致 N dB」は、つなぎ目の前後各 8 フレームでの 2 本のテイクの近さです。縮小した映像の PSNR で測ります。約 22 dB 未満で赤くなるのは、この位置で差が大きく、つなぎ目の修復に失敗する可能性があるためです。この境界は目安にすぎず、校正していません（[実測データ](#実測データ)を参照）。
- 2 か所の範囲が重なる場合は、つなぎ目の上の小さな三角をクリックすると、そのバーを最前面に表示します。
- 旧ワークフローにすでにあるつなぎ目は、ドラッグかダブルクリックをするまで、従来の両側各 1 セルを再生成する範囲を保ちます。

1. **N テイク生成**：クリップ全体を N 回生成するジョブをキューに追加し、シードは順に増やします。N はボタン横の「テイク数」で変更でき、プロジェクトページのプリセットと同じ設定です。生成中はページ上部にライブプレビューが表示され、意図と違えばすぐに中断できます。実行するのはこのノードと後ろに接続した出力ノードだけで、ワークフロー内の別のディレクターノードや無関係な保存ノードは実行しません。
2. **採用**：ショットごとに、左のプレーヤーと右のテイク一覧があり、各テイクのそのショット部分から 1 本を採用します。カードをクリックすると左で再生します。プレーヤー下の「全ショット採用」で表示中のテイクを全ショットに使うか、削除できます（テイクはクリップ全体の 1 回の生成なので、削除すると全ショットの一覧から消えます。ファイルは出力ディレクトリに残ります）。カードは幅に合わせて折り返し、多い場合は一覧内を縦にスクロールします。ショット見出しの右にはそれぞれ「プレビューサイズ」のスライダーがあり、最小にするとリストになります。カードとプレーヤーは、そのテイクで実際にカットインしたフレームからカットアウトしたフレームまでを再生します。指定したフレーム番号で機械的に切り取るわけではありません（モデルのカットは数フレームずれます。[実測データ](#実測データ)を参照）。停止中のカードにはショット中央の画像が表示され、マウスを重ねると先頭から再生します。左の細いナビゲーターは 1 区画が 1 ショットで、高さがショット長に比例し、色で状態（「採用済み」「テイクあり」「未生成」）を示します。赤線は上のタイムラインの現在位置です。ウィンドウの高さに合わせて伸縮し、クリックするとそのショットへ移動します。
3. **最終クリップ**：全ショットでテイクを採用すると「合成」ボタンが表示され、実行すると最終クリップができます。最終クリップは別のファイルとして出力され、出力ページに並びます。完了すると、ここに「出力を表示」が現れます。処理内容は採用したテイクによって変わります。
   - 全ショットで同じテイクを採用 → そのテイクを最終クリップとして直接出力します。モデルは使わず、再エンコード 1 回だけで、2〜3 秒で完了します。
   - テイクの切り替えがすべてカットの位置 → 各区間をモデルに通さずそのままつなぐので、数秒で終わります。つなぐ位置は指定フレームではなく、両テイクが**実際に**カットしたフレームです。前のショットのテイクが後のショットのテイクより早くカットしている場合、間の数フレームはどちらのショットにも属さないので取り除きます。そのため、完成クリップが数フレーム短くなることがあります。逆の場合は両方のテイクが合うフレームがあるので、そこでつなぎ、長さは変わりません。完了後に実際の長さが表示され、「接続記録」に各カットの処理が残ります。音声は既定で映像と同じフレームで新しいテイクへ切り替わります。音声リンクがつながっているカットでは、カット前のテイクの音声を続けます（「接続記録」に `the sound stays with …` と記載します）。
   - 長回しの途中でテイクを切り替えた → つなぎ目付近の短い区間を再生成します。範囲は上記の帯で設定します。それ以外は音も含め採用したテイクを使い、再生成せず、エンコード・デコードを 1 回通るだけです（[既知の制限](#既知の制限)を参照）。再描画範囲はその長回しの外へ出ず、どのテイクの実際のカット位置にも触れません。強度は[仕上げページ](#仕上げページ)で調整します。同じ処理内のカットは、そのまま編集でつなぎます。

> [!NOTE]
> テイクに「このショットだけ再生成」という操作はありません。モデルは毎回クリップ全体を計算する必要があります。1 ショットだけを計算し直しても、別のテイクを生成するのと同じコストがかかり、生成済みの映像を起点に再生成することになります。もう一度試す場合は、別のテイクを生成してください。（**ソース動画**の一部のセルだけを描き直すのは別の操作で、編集ページの「部分再描画」を使います。）

カットで区切られたショットなら、テイクは自由に組み合わせられます。長回し内で切り替えるには、つなぎ目での映像が似ている必要があります。帯の一致の値が測るのはこの近さです。同じソース動画、または同じ先頭・最終・中間のフレームを指定したテイクは通常、動きが似ており、つなぎ目の再描画で不連続をならせます。ただし保証はありません。実測では、同じソース動画を使った 1 組のテイクで、シードによって同じシーンの光と色調が大きく異なり、試した範囲と強度ではいずれもつながりませんでした。制約のないテキストからの動画生成では各テイクが別々の映像なので、つなぎ目を描き直してもつながらず、どこかのフレームで画面が飛びます（[実測データ](#実測データ)を参照）。

テイクには生成時のクリップ長が記録され、長さを変えると以前のテイクは採用できなくなります。生成時のショットの区切り（カットの位置、どのショットが 1 本の長回しか）も記録されます。あとで区切りを変えても以前のテイクは採用できますが、生成ページがそのテイクに印を付けて知らせます。映像の中のカットは当時の位置のままで、あとから変わることはありません。今の区切りに合わせるには、テイクを生成し直してください。合成結果にも採用内容が記録され、採用を変えると以前の合成クリップは最終クリップとして表示されなくなります。

### 仕上げページ

完成クリップができた後の処理と、表示・保存の設定です。

![仕上げページ：完成クリップのつなぎ方とつなぎ目の設定](docs/ja/post-join.jpg)

**合成**：ショットごとに採用したテイクを 1 本につなぎます。そのまま編集でつなぐカット、描き直す長回し内のつなぎ目、音声を継続するカットの数を表示します。ここから「合成」を実行できます。描き直すつなぎ目がなければモデルは使いません。描き直すつなぎ目がある場合、「保持フレーム数」に、合成後の各ショットで採用したテイクの映像が何フレーム残るかを表示します。残りはつなぎ目の再描画範囲に入り、新しく生成した映像に置き換わります。長回し内で 2 つのつなぎ目に挟まれた短い区間は全体が覆われることがあり、その場合は「採用映像なし」と赤字で表示します。長回しが短すぎて必要な再生成範囲が入らない場合も、つなぎ目を処理できないことを赤字で示します。次の 2 項目は長回し内のつなぎ目にだけ作用します（テイクの切り替えがすべてカットの位置なら、両方ともグレーアウトします）。

- *再生成範囲*：つなぎ目の前後で再生成するフレーム数を表示します。範囲は[生成ページ](#生成ページ)のタイムライン下の帯で両端をドラッグして設定し、ここでは読み取り専用です。
- *つなぎ目強度*：1（既定値）は範囲内を一から生成し直します。下げると両テイクの元の映像がより多く残ります。2 セル全体を描き直す場合、似た 1 組のテイクでは 0.3 でもつなぎ目をならせました。自動範囲の 12 フレームでは、0.3 は 1 より効果が低くなりました（[実測データ](#実測データ)を参照）。横に、計算した開始時のノイズの割合を表示します。（ノードの `sigmas` 入力に外部スケジュールを接続した場合、強度は作用しません。）

![仕上げページ：顔のリファイン前後を並べ、両方とも顔の位置にズーム](docs/ja/post-face.jpg)

**顔のリファイン**：画面の中で小さい顔は割り当てられる画素が少なく、ぼけたり崩れたりしやすくなります。完成クリップの主な顔の周辺を切り出し、顔に十分な画素があるサイズでもう一度生成して、元の位置へ戻します。その範囲外の画素は一切変えず、音は完成クリップのものを使い、リファイン前のクリップも残します。ページでは前後を並べ、再生もフレーム移動も同期します。画面をクリックすると両方がその位置にズームし（画像はズーム後）、もう一度クリックすると元に戻ります。

- *顔の参照対象*：素材の人物を選ぶと、その人物の画像を参照して描き直します（参照モデル）。
- *対象ショット*：既定は「自動（顔が約 24〜80 ピクセルのショット）」です。より小さい顔は貼り戻しても細部を保持できず、大きい顔はもともと鮮明なので、描き直しても別の顔になるだけです。番号を押すと、顔の大きさに関係なく選んだショットだけを処理します。顔が見つからないショットは変えません。該当するショットがなければ実行に失敗し、各ショットを除外した理由をページに表示します。
- *描き直す強さ*：既定値は 85%。このモデルは 70% 未満ではほぼ元の映像を再現するため、直感よりもかなり高い値になります（[実測データ](#実測データ)を参照）。
- 顔が見つからない区間が長い場合（人物が後ろを向いたり画面外へ出たりした場合）は貼り戻しません。数フレームの検出抜けは前後をつないで貼り戻し、顔が再び見つかると処理を再開します。
- 1 ショットで処理するのは、最も長く映っている 1 つの顔です。ショットが違えば別の人物を選ぶこともあります。「顔の参照対象」は再描画時の参照画像を決めるだけで、検出した顔の選択には使いません。複数人のクリップでは、「対象ショット」でその人物が主役のショットだけを残してください。
- 現在のプリセットを使い、その画素数で顔の周辺を正方形として生成します（`Standard` は 640×640）。所要時間はクリップ 1 本の生成とほぼ同じです。

**ライブプレビュー**と**保存**（ファイル名の接頭辞、ファイル形式、映像コーデック）は、このノードのすべての実行に作用し、プリセットには属しません。

### 出力ページ

ComfyUI の履歴（直近 40 件）から、このクリップの実行結果を読み込みます。直接実行したクリップ、合成した最終クリップ、顔のリファイン結果を、それぞれの実行レポートと実行時にモデルへ送ったプロンプトとともに表示します。テイクをカットでつないだだけで何も生成し直していない最終クリップは「直接接続（N ショット・再生成なし）」と表示し、ステップ数やシードは出しません（その実行では映像を生成していません）。テイクはここではなく生成ページにあります。クリップの内容（素材、プロンプト、再描画範囲）を変えると、以前の結果に「生成後にクリップが変更済み。」と表示します。顔のリファイン結果にはここでこの表示を付けません。最後のリファイン結果が現在のクリップに合っているかは仕上げページで確認できます。プリセットやシードだけの変更は対象外です。合成した最終クリップでは再描画範囲をここでは比較せず、つなぎ目の設定や採用を変えた場合は生成ページで古くなったことを示します。

## 時間セル

H3 の動画 VAE はフレーム 0 から 17 フレームずつ独立してエンコードし、残りの 5 フレームを末尾に置きます。そのため、124 フレームのクリップは 17 フレームのセルが 7 個（0–16、17–33…102–118）と、末尾の 5 フレームのセルが 1 個（119–123）になります。

1 セルは 5 個の latent フレームになります。セルの先頭の動画フレームが 1 個を占め、続く 16 フレームは 4 フレームずつ 1 個になります。末尾の短いセルは 1 + 4 フレームで、latent フレーム 2 個です。マスクは latent フレーム単位なので、**個別に保持・再生成できる最小単位は 1 個の latent フレーム（動画の 4 フレーム分。ただし各セルの先頭は 1 フレーム分）で、1 セルではありません**。

セルが重要なのはエンコード時です。各セルは個別にエンコードされ、セル内では因果関係があり、後ろの latent フレームは同じセルの前の映像に依存します。後続のセルには依存しません。ここから実測で得た指針は、**再生成範囲をセル境界で終えるのがよい**ということです（[実測データ](#実測データ)を参照）。セルの途中で終えると、同じセル内でその後に保持する latent フレームは、すでに置き換わった前の映像をもとにエンコードされているため、新しい映像と整合しません。測定した 1 組のテイクでは、直後の 1–2 フレームが元のテイクから 3–5 dB 遠くなり、次のセルへ 1 フレームだけ入る範囲ではつなぎ目がつながりませんでした。範囲の開始位置にはこの制約はありません。デコード側にセルの境界はなく、デコーダーは 7 個の latent フレームを一度に読み、隣接するウィンドウ間で 5 フレームをブレンドします。そのため「保持」は「再生成しない」という意味で、「ピクセルが変わらない」ことではありません。再生成範囲付近の保持フレームは、2 回の実行間での一致が約 38 dB にとどまりますが、この差は見た目では分かりません。

タイムラインのセル帯は「選択セル」用で、セル全体を選びます。「ソース再描画」の場合だけ表示するのは、その場合だけ「元のまま」を選べるためです（ゼロから生成する場合は全セルを描き直します）。長回し内のつなぎ目の再生成範囲は latent フレーム単位で指定します。[生成ページ](#生成ページ)の範囲帯を参照してください。モンタージュのカット点はセルとは無関係で、そこでは描き直しません。

## プロンプトの組み立て方

構造化形式では、MiniMax の 2 つの公式プロンプト作成ガイドに従って組み立てます。

- **ベースモデル**：`integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music` の 3 フィールドです。先頭、最終、または両方のフレームがある場合は、公式の固定の画像対応文を先頭に追加します。
- **参照モデルで、宣言する素材がある場合**：`subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music` の 6 セクションです。`summary` 冒頭のタスク種別（`reference generation`、`video editing`、`video continuation`、`keyframe completion`、`audio reuse`、`audio reference`）は素材の役割から決まります。その後の 1〜2 文（パネルの「概要」）は自分で書きます。ソース動画の編集や続きの生成では公式の冒頭文を自動で加えるため、空欄で構いません。自動補完後も空なら、「最終プロンプト」に案内が表示されます。
- **参照モデルで、宣言する素材がない場合**：ベースモデルと同じ 3 フィールドです。

これは形式の枠組みで、空欄のフィールドは出力しません。BGM だけは例外で、空欄なら `non_diegetic_music: N/A` を出力します。たとえば環境音が空なら `overall_soundscape` は出力せず、「最終プロンプト」に、公式ガイドでは必須とされている旨を表示します。

**番号は自動で付きます。** 画像のある対象は一覧の順に `<Subject 1>`、`<Subject 2>`…となります。その画像が `<Picture N>` の番号を先に使い、続いてモデルに宣言する先頭・最終・途中のフレームと絵コンテを時刻順に並べます。動画は一覧順です（ソース動画の編集、続きの生成、動きの参照に使う場合は、それが `<Video 1>`）。音声は参照動画で有効にした音声トラックを先に並べ、単独の音声が続きます。プロンプトの `@名前` は対応する番号に置き換わります。テキストだけの対象は番号を使わず、`@名前` が説明文に直接置き換わります。ベースモデルで名前を指定できるのは対象だけで、モデルに「見せる」のはクリップ全体の先頭・最終フレームだけです。それ以外の位置の画像は、そのフレームに固定しますがプロンプトには入りません。

この部分は同梱の上流プロジェクトのプランナーが処理します（[NOTICE](NOTICE)を参照）。

参照素材の公式上限は、画像 9 枚、動画 3 本（合計 15 秒以内）、音声 3 本（参照動画の音声も含む）、全体で 12 ファイルです。対象は画像の有無にかかわらず最大 9 個です。数の上限を超えるとページに理由を表示し、実行を拒否します。長さはファイルを読んで初めて分かるため、「最終プロンプト」と実行開始時に確認します。各参照動画（ソース動画も含む）はクリップと同じ長さまで読み込み、最大 15 秒だけモデルへ渡します。それ以上は短くして案内を表示します。実際に渡す区間の合計が 15 秒を超える場合は実行を拒否します。素材を黙って除外せず拒否するのは、除外すると後の番号がすべてずれるためです。

## ノードの上流に接続するもの

ノード自体はモデルをロードしません。拡散モデルは上流のローダーで読み込み、`MODEL` 入力から渡します。そのため、モデルにパッチを適用するものはすべて `model` / `model_turbo` の上流へ接続し、パネルで認識する必要はありません。

- **LoRA、高速化 LoRA**：`LoraLoaderModelOnly`。
- **Fun ControlNet Union**（公式の構造制御 / 局所的な再描画の方法）：`ModelPatchLoader` + `Apply MiniMax H3 Fun ControlNet` の出力を `model` に接続します（`Draft` を使う場合は `model_turbo` 側にも接続）。制御動画は 24 fps で、クリップの先頭フレームから始まるものを用意してください。パッチがクリップの長さと画面サイズに合わせます。
- **FastH3**（FastVideo の 8 ステップ蒸留モデル）：`UNETLoader` → `ModelAttentionBackend` → `BlockSparseAttention` を `model` に接続し、プリセットのステップ数を 8、スケジュールのシフトを 10 / 3 にします。

## 実測データ

以下は開発時のテスト（ComfyUI 0.39.0）による数値です。動作を説明するもので、性能を保証するものではありません。

測定方法：2 本の動画間の PSNR はフレームごとに計算して平均し、「フレーム間変化」は隣接する 2 フレームの画素差の絶対値を平均します。長回しのつなぎ目の数値は `tests/measure_seam.py`（2 本のテイク、合成クリップ、つなぎ目のフレーム番号を指定）、セル間の独立性は `tests/measure_vae_cells.py` で測定しました。特記のないものは下書き設定（高速化 LoRA、672×384 程度、124 フレーム）です。各数値は 1 回の実行によるもので、複数のシードでの統計は取っていません。

**「変更量」は線形ではありません。** モデルのスケジュールにはシフト（shift）があります。パネル自身のスケジュールを使う場合、シフトを s、変更量（denoise）を d とすると、開始時のノイズの割合は s·d / (1 + (s−1)·d) です（外部の `sigmas` を接続すると変更量は作用せず、開始時のレベルは指定した sigma で決まります。この場合はパネルに率を表示せず、実行レポートに `external sigmas` と記載します）。

| 変更量（シフト 12） | 開始時のノイズ |
|---|---|
| 0.85 | 98.6% |
| 0.70 | 96.6% |
| 0.30 | 83.7% |
| 0.15 | 67.9% |
| 0.05 | 38.7% |

そのため、元のクリップの大部分を残すには、変更量を直感よりもかなり低く設定する必要があります。パネルでは横にこの率を表示し、顔のリファインの「描き直す強さ」ではこの率を直接指定します。ベースモデルでの実測では、0.7 はまったく別の動画になり、0.3 は構図と動きを保って細部を描き直し、0.15 はほぼ元の動画のままでした。

**同じシードでも同じクリップになるとは限りません。** 公式テンプレートを変更せずに 2 回実行した結果は、フレームごとの PSNR が 19–20 dB でした。Gacha Director と公式テンプレートの差も同程度でした。結果を残すには、そのファイルを保存してください。

**長回し内のつなぎ目の再描画（同じソース動画を使うテイク）。** 2 本のテイクをセル境界でつなぐと、直接カットした場合のフレーム間変化は通常の 1.7 倍になりました。つなぎ目を描き直すと通常の水準に戻りました。再生成せず残したセルと採用したテイクとの比較は 31–34 dB です（VAE のエンコード・デコード 1 往復による損失）。強さを 1 から 0.3 に下げてもつなぎ目は同じようにならされ、描き直したセルは採用したテイクにより近くなりました。

**モデルのカット時刻は正確ではないため、実際のカット位置でつなぎます。** プロンプトのカット点は時刻（`[Shot 2] At 00:02.833`）で指定しますが、モデルはフレーム単位で正確に実行しません。2 ショット、124 フレームのテキストからの動画生成を 8 本試すと、指定フレームでカットしたものが 4 本、1 フレーム遅いものが 3 本、1 フレーム早いものが 1 本でした。ショット数と長さが増えるとずれも大きくなります。4 ショット、243 フレーム（約 10 秒）の下書きテイク 8 本では、指定カット点がフレーム 61、122、183 に対し、最初は 0–3 フレーム遅れ、2 つ目は 4–8 フレーム早く、3 つ目は 1–9 フレーム早く切れました。同じクリップを `Standard` で 1 本生成すると、各カットは 2、11、13 フレーム早く、下書きプリセットだけの問題ではありません。3 ショット、362 フレーム（15 秒）の下書き 1 本では、2 つのカットが 6 フレームと 18 フレーム早く切れました。カットの後の各ショットを "The shot cuts." で始めても、公式の例にならって "the camera cuts to …" と書いても（上の 8 本のうち最初の 4 つのシードで各 1 回）、カットは正確になりませんでした。2 番目と 3 番目のカットは 1〜8 フレーム早いままで、書かない場合は 1〜9 フレームでした。そのため、パネルがこうした文言を自動で足すことはありません。

その 8 本のうち 4 本を各ショットに 1 本ずつ採用し、3 通りの方法でつなぎました。

| つなぎ方 | 結果 |
|---|---|
| 指定したフレーム番号で直接つなぐ | 本来 3 回の切り替えが 6 回に。カット点に別ショットの映像が 3、6、3 フレーム混入 |
| 両テイクの実際のカット位置でつなぐ（現在のパネルの方法） | ちょうど 3 回のカットで、余分なフレームなし。どちらにも属さない 3 フレームを取り除き、完成クリップは 240 フレーム。モデルを使わず、コールドスタートのサーバーで 5 秒 |
| つなぎ目を再描画（以前のパネルの方法） | 切り替えは 3 回だが、15 セル中 9 セルを描き直し、各ショットの採用テイクは 34、17、0、39 フレームしか残らなかった。カット点はフレーム 62、130、194 に移動。196 秒 |

実際のカット点の検出方法：比べるのは明るさではなく、画面内の明暗の配置です。各フレームから全体の明るさを取り除き、コントラストをおおむねそろえたうえで（非常に暗い画面や平坦な画面は無理に引き伸ばしません）、前のフレームとどれだけ違うかを測ります（同じ画面ならほぼ 0、無関係な 2 つの画面ならほぼ 1）。こうすると、稲妻や爆発でショットが明るくなっても変化は小さく、ショットが切り替わったときだけ大きくなります。カットのフレームは 0.28〜1.21 で、通常のフレーム間変化の 4〜800 倍です（パネルのしきい値は 5 倍。全体が激しく動くクリップでは通常の変化そのものが大きく、カットがその 5 倍に届かないことがあるため、しきい値は 0.5 を上限にしています）。さらに、カットの前後それぞれで、カットに接する 8 フレームとその外側の 8 フレームのうち、いずれも 6 フレーム以上が反対側と違って見えることを確認します。これで、フラッシュや 0.5 秒程度までの光のまたたきを除外します（そのあと画面は元に戻りますが、カットでは戻りません）。最後に、カット前の 4 フレームとカット後の 4 フレームを 2 つのグループとして比べます。グループ同士の差が、各グループ内のばらつきの 2 倍以上あることを求めます。ちらつく光や、続いている大きな動きはこれを満たしません。（クリップの先頭・末尾の近くや、指定されたごく短いショットの隣では、存在するフレームだけで判定します。）

より難しい題材 3 つでも、下書きを 4 本ずつ測定しました。暗い鍛冶場（4 ショットすべてに同じ人物、クローズアップが 2 つ続き、どのテイクにもハンマーの打撃や火花、加工物が素早く画面外へ出る動きが 2〜3 か所あり、最大で通常の 34 倍の変化）：12 個のカットをすべて検出でき、指定フレームとのずれは −2〜+4 フレームでした。夜の雷雨（稲妻が何度も画面を照らし、暗いショットでは見えていなかったものまで映し出す。最大で通常の 105 倍の変化）：12 個のカットをすべて検出できました。稲妻のまたたきが終わった直後にディゾルブ気味のカットが来る箇所も含みます。同じ雷雨のテイクを明るさの差で検出すると（以前の方式）、正確なのは 12 個中 5 個だけで、残りは 1〜22 フレームずれました。激しいアクション（手持ちの追跡、モーションブラーのかかった足元のクローズアップ、爆発、ウィップパン）：12 個のカットをすべて検出できました。こうしたショットでは、指定していない箇所でモデルがショット内の映像を飛ばすことがあり、その変化はカットと同じ大きさになります。同じくらいの大きさ（差が 15% 以内）の変化が 2 つあるときは、指定フレームに近いほうを採用します。実測では 2 回あり、カットは指定フレームから 1 フレームと 4 フレーム、飛びは 7 フレームと 17 フレームの位置でした。ここまではすべて下書きサイズのテイクです。雷雨とアクションの 2 つは Standard プリセットでも 2 本ずつ生成し、12 個のカットをすべて検出できました。

モデルがカットではなくディゾルブやウィップパンを生成した場合は検出できないことがあり、そのときは指定フレームでつなぎます。

**長回しは途中で切れません。** 4 区間、243 フレームのクリップで、最初の 3 区間を 1 つの長回し、4 区間目をカットに設定しました（下書きプリセット、2 シード）。両方とも 4 区間目の先頭で 1 回だけカットし（指定より 7 フレームと 11 フレーム遅れ）、最初の 3 区間は切れない 1 ショットで、動作は文章の順に進みました。全 4 区間を 1 つの長回しにした 2 本には、カットがありませんでした。連続する区間を 1 つの `[Shot]` にまとめる方法は有効ですが、各区間が何秒目に起きるかはパネルで制御できません。

**長回しでテイクを切り替えても、似ていない映像はつながりません。** 上の長回し 1 ショットの 2 本は、別々の映像です（テキストからの動画生成、異なるシード）。前半に 1 本目、後半に 2 本目を使い、フレーム 122 でつなぎました。強さ 1 では描き直した 3 セルが 1 本目の映像を続け、画面の飛びが再描画範囲の末尾へ移りました（フレーム 153、フレーム間変化は通常の 25 倍）。強さ 0.3 では両側が元のまま残り、飛びはフレーム 122 に残りました。どちらもつながりませんでした。この処理が役立つのは、もともと似ているテイク同士だけです。

**再生成範囲：何フレームを描き直し、どこで止めるか。** `tests/measure_seam_range.py` で、似た 1 組のテイクを測定しました。[一通りの例](#一通りの例実写映像を雪景色に変える)の編集を 2 つのシードで生成したもので、下書き設定、124 フレーム、範囲帯の一致の値は約 33 dB です。先頭 68 フレームに 1 本目、その後に 2 本目を使い、再生成範囲だけを変えました。強度はすべて 1 です。「飛び」は合成クリップのつなぎ目付近で最大のフレーム間変化を、2 本のテイク自体の同じ位置の変化で割った値です。テイク自体の動きは約 1 倍で、それを明らかに上回る場合はつなぎ目で映像が飛んでいます。「保持フレームへの影響」は、範囲直後の保持フレームが、再生成せずエンコード・デコードを 1 回通した同じフレームに比べて、採用したテイクからどれだけ遠くなったかです。フレーム 68 はセル境界上にあります。

| 再生成するフレーム | フレーム数 | 飛び | 保持フレームへの影響 |
|---|---|---|---|
| 再生成せずハードカット | 0 | 3.0 倍 | – |
| 再生成せずエンコード・デコード 1 回 | 0 | 2.4 倍 | – |
| 64–67 | 4 | 1.6 倍 | 0.4 dB |
| 60–67 | 8 | 1.5 倍 | 0.5 dB |
| 56–67（自動範囲） | 12 | 1.3 倍 | 0.0 dB |
| 52–67 | 16 | 1.4 倍 | 0.1 dB |
| 64–68（次のセルへ 1 フレーム入る） | 5 | 2.0 倍 | 4.5 dB |
| 56–68（次のセルへ 1 フレーム入る） | 13 | 2.1 倍 | 4.8 dB |
| 60–72（セルの途中で終える） | 13 | 1.2 倍 | 3.6 dB |
| 56–76（セルの途中で終える） | 21 | 1.1 倍 | 3.6 dB |
| 60–84（次のセルの末尾まで） | 25 | 1.1 倍 | 1.6 dB |
| 51–84（従来の方法：両側各 1 セル全体） | 34 | 1.3 倍 | 1.6 dB |

この表から分かること：

- セル境界で終える範囲（67 で終わる 4 行）は、その後の保持フレームへの影響がほぼありません（0–0.5 dB）。セルの途中で終えると 3.6 dB です。次のセルへ 1 フレームだけ入る場合は飛びが残ります（2 倍）。次のセル全体も再生成する 60–84 は飛びが最小ですが、影響は 1.6 dB で、2 本目のテイクの映像がさらに 17 フレーム置き換わります。
- 4 フレーム、8 フレームでも改善しますが、12 フレームほどではなく、16 フレームでも改善は増えません。自動範囲の「少なくとも 12 フレームを目標に、セル境界で終える」はこの表をもとに決めました。自動範囲の行は、別の 2 シードでも測定しました（1.27 倍、1.25 倍、影響は 0.4、0.1 dB）。さらに 2 本を入れ替えて 1 回つなぐと、1.18 倍、0.5 dB でした。
- 同じ 12 フレームでも、強度 0.3 は 1.5 倍で、強度 1 より効果が低くなりました。
- つなぎ目がセルの途中、フレーム 62 にある場合（ハードカット 4.4 倍、エンコード・デコードのみ 3.6 倍）、そこを含む 4 フレーム（60–63）だけの再生成は 2.1 倍です。56–67（セル末尾までの 12 フレーム）は 1.3 倍、影響 0.9 dB、従来の方法（34–84、51 フレーム）は 1.4 倍、影響 1.9 dB でした。セルに入った直後のフレーム 70 では、64–84（21 フレーム）が 1.3 倍、影響 1.6 dB でした。

いずれもこの 1 組のテイクでの結果で、特記したもの以外は各数値につき 1 回の実行です。12 フレームは現在の既定の方法であり、測定で求めた普遍的な下限ではありません。つなぎ目の音声は測定していません。

**差の大きい 1 組では、試した範囲と強度のいずれもつながりませんでした。** 別の 1 組も同じソース動画とプロンプトを 2 シードで生成しましたが、動きが大きく、シーンの光と色調も大きく異なりました。範囲帯の一致の値は約 19 dB です。つなぎ目は同じフレーム 68 で、ハードカットは 2.1 倍、エンコード・デコードのみは 2.0 倍でした。セル境界で終える 8、12、16 フレームはすべて 2.0 倍で、飛びは元の位置に残りました。両側合わせて 13 フレームは 1.8 倍、25 フレームと 34 フレームは 1.9 倍で、飛びが範囲の末尾（フレーム 85）に移りました。強度 0.3 で 25、34 フレームを再生成すると 1.9 倍、1.8 倍で、飛びはつなぎ目に残りました。そのため範囲帯に一致の値を表示しています。赤くなる境界の 22 dB は、この 2 つの実測点の間に置いただけで、校正していません。現在分かっているのは、約 33 dB のこの 1 組はつながり、約 19 dB のこの 1 組はつながらなかったことだけです。

**セリフは書いたとおりに発話されます。** 下書きで 2 本を生成しました。テキストからの動画生成では高齢のパン職人が 1 行を話し、参照生成では同じキャラクターが 2 ショットでそれぞれ 1 行を話します。ローカルの音声認識で完成クリップの音声を文字に起こすと、3 つのセリフともプロンプトと完全に一致し、2 ショット目のセリフもそのショットの時間内に収まりました。声質の参照も 2 回試しました（高めの声と低い声を、それぞれ同じキャラクターに指定）。セリフは一字一句そのままで、参照音声の言葉は写されませんでした。発話の基本周波数は参照に従いました（参照 232 Hz → 結果 235 Hz、参照 131 Hz → 結果 142 Hz、参照なしの 3 本は 157–198 Hz）。音色がどれだけ似て聞こえるかは、ここでは測定できません。

**参照動画のサイズが速度を左右します。** 画面サイズとステップ数が同じ場合、参照動画の短辺が 512 では 1 ステップ約 15 秒、256 では約 6 秒でした。

**顔のリファインは数十ピクセルの顔には有効ですが、それより小さくても大きくても役立ちません。** 864×480 の全身が映るロングショット（`Standard`、124 フレーム、顔は約 38 ピクセル、途中で後ろを向く区間あり）を、同じプリセットで 4 つの強さで各 1 回リファインしました。

| 描き直す強さ | 結果 |
|---|---|
| 50% | リファイン前とほぼ違いなし |
| 70% | ぼけた顔のパーツが少し整った |
| 85% | 目・鼻・口が鮮明になり、振り向く際の横顔もきれい。髪形、頭の向き、照明は変わらなかった |
| 93% | 顔は最も鮮明だが、髪や顔の周りの背景も変わった |

別の 672×384 の下書きクリップには、異なる 2 種類の顔サイズがありました。ロングショットの約 14 ピクセルの顔は、85% でも顔の細部に改善が見られず、周囲のもの（服の色）が変わりました。クローズアップの約 160 ピクセルの顔は、50% では違いがなく、85% では別の、より写実的な顔になりました。そのため、自動モードでは約 24–80 ピクセルの顔だけを処理します。24 と 80 の境界は細かく検証した値ではなく、「14 ピクセルは効果なし、38 は有効、160 は有害」という 3 つの実測点の間から選んだものです。所要時間は、124 フレームのクリップ生成が 359 秒、4 回のリファインが各 349–370 秒でした。

**クリップ全体の再生成：同じサイズでは効果がなく、拡大すると有効ですが高コストです。** 同じ 864×480 のロングショットで、開始時のノイズを 85% にして各 1 本試しました。元のサイズで再生成（394 秒）すると、構図と動きは変わらず、細部は入れ替わりましたが、顔は同じようにぼけたままでした。1344×768 に拡大してから再生成（2035 秒、同時にほかの作業も実行）すると、構図と動きを保ち、顔や服の細部が明らかに鮮明になりました。ただし、すべての細部が描き直され、元動画とは同一ではありません。比較として、同じシードで直接 1344×768 を生成（1613 秒）すると、構図がまったく違う別の動画になりました。今回の比較で構図を保てたのは「小さいサイズで採用を決め、拡大して描き直す」方法だけで、もう一度大きいサイズで生成する時間がかかります。

**顔検出。** 検出器は kornia の YuNet です。RGB 順で映像を渡すと、ロングショットの小さな顔が見つからず、雪の上の岩や雲が顔と判定されました（スコア 0.7）。学習時の BGR 順に変えると、同じ映像内の 14 ピクセルの顔がスコア 0.9 で検出されました。4 ショットの下書きテイク 8 本では、クローズアップの顔は 89–93% のフレームで検出されました。ロングショットの小さな顔は、4 本で 98% 以上、残りの 4 本で 2–48% のフレームで見つかりました。人の顔がない 2 ショット（ドラゴン）では、0–36% のフレームでドラゴンの頭を顔と判定しました。処理対象とするには同じ顔の検出フレーム数がショットの 4 割以上必要です。その 2 ショットは 8 本のどれでも条件を満たさず、誤って処理されたものはありませんでした。

**名前を指定しなくても素材は認識されますが、指定が最も確実です。** 第 2 ショットだけに属する対象（犬の画像 1 枚）を、3 通りの書き方で各 2 シード試しました（下書きプリセット）。ショットの説明で `@名前` を使って指定する、指定せずパネルに「このショットに登場する」という文を補わせる、指定もショットへの割り当てもせず冒頭で宣言するだけ、の 3 通りです。6 本とも第 2 ショットに犬が登場しました。名前を指定した 2 本は、どちらも参照画像と同じ白黒の犬でした。自動で文を補った 2 本も同じ犬でしたが、1 本には別の動物も出ました。宣言だけの 2 本は、1 本は毛色が合い、もう 1 本は違いました。各 2 本なので比率を論じることはできず、3 通りとも機能することだけを示します。「誰が何をするか」を区別させるには、名前を指定してください。


## 既知の制限

- **固定してもピクセル単位で同一にはなりません。** フレームに固定した画像はコンディショニングによる制約です。再生成せず残すセルも VAE のエンコード・デコードを 1 回通ります。元動画に近くても、そのコピーではありません。
- **カット時刻はモデルが決めます。** 2 ショットの短いクリップはおおむね 1 フレーム以内ですが、ショット数や長さが増えると十数フレームずれます（[実測データ](#実測データ)を参照）。音楽に合わせるなど、時刻を正確にしたい場合は、現状では多くのテイクから選ぶか、複数ノードで別々に生成して編集ソフトでつなぐ必要があります。
- **編集でつなぐと数フレーム短くなることがあります。** 同じカット位置で、前のショットのテイクが後のショットのテイクより早くカットしている場合、間のフレームはどちらのショットにも属さないので取り除きます。実際の長さは生成ページに表示し、その後の顔のリファインもその長さを使います。
- **カットでつないだクリップは、カットの位置で音量に段差が出ます。** 各ショットの音は、そのショットで採用したテイクのものです。モデルが生成するテイクは、全体の音量がそれぞれ違います。4 本のテイクをつないだ 10 秒のクリップで測ると、3 か所のカットの前後で +15、−9、−5 dB の差があり、いずれも音声の切り替えによるものでした。パネルはラウドネスをそろえません（ショットごとに音量が違うのは本来のことで、ショット単位でそろえると音の抑揚がなくなります）。気になる場合は、そのカットの音声リンクをつないで全体を 1 本のテイクの音声にするか、編集ソフトで通しの音声トラックに差し替えます。同じクリップで 3 か所ともリンクすると、カット前後の差は −1、+18、−2 dB でした。この +18 は、そのテイク自体の音声イベントによるものです。そのテイクだけを聞いた場合、同じ位置の差は +15 dB でした。継続する音声は別のテイクのものなので、口の動きやアクションのタイミングに合わないことがあります。環境音や BGM 向けで、セリフには適しません。
- **カット検出は映像の急変に依存します。** ディゾルブ、ウィップパン、似た映像のショット間では実際のカットを見つけられず、指定フレームでつなぐことがあり、別ショットの数フレームが混入する可能性があります。カットのすぐそばで稲妻や爆発の光がまたたくと、検出されるカット位置が数フレームずれる可能性は残ります（実測した 12 か所では起きませんでした）。また、何も映っていない画面同士のカット（真っ黒から真っ白へ）は検出できません。「接続記録」に `no cut found` と記載します。手動でカット点を指定する機能はありません。
- **長回し内の各区間の時刻は制御できません。** 公式のプロンプト形式にショット内の時間指定がなく、パネルが保証するのは順序だけです。
- **長回し内のテイク切り替えは、つなぎ目で映像が似ている場合にだけ有効です。** 同じソース動画や同じ先頭・最終フレームなら通常は近くなりますが、保証はありません（[実測データ](#実測データ)を参照）。異なる映像はつなぎ目を描き直してもつながらないため、その長回しの全区間で同じテイクを採用してください。後半だけを変えたい場合は、似たテイクを手作業で作れます。編集ページで、採用したテイクをソース動画に選びます（ファイル一覧には生成済みのクリップも出ます）。「ソース用途」を「ソース再描画」にし、「部分再描画」の「再描画範囲」を「選択セル」にして、区切りより後ろの範囲を指定します（例：`f122-242`。タイムラインのセル帯をクリックしても指定できます）。ほかの設定は変えず、いつもどおりテイクを生成します。実測（下書き、シード 2 つ、119 フレーム目から描き直し）では、先頭の 119 フレームは元のテイクと一致し（エンコード・デコード 1 回、PSNR 38 dB）、新旧の境目のフレーム間変化は通常の 1.0 倍（飛びなし）、後半はシードごとに違う新しい映像で、余分なカットもありませんでした。1 本あたり 163〜175 秒です（ゼロからの生成は約 2 分）。新しいテイクの前半は元のテイクそのものなので、その長回しの全区間で新しいテイクを採用してください。終わったらソース動画を外し、「再描画範囲」を「クリップ全体」に戻すと、ゼロからの生成に戻ります。パネルにこの操作を 1 ステップで行う機能はありません。自動範囲では、つなぎ目 1 か所で 12〜21 フレームを再生成します。範囲を広くドラッグした場合や、旧ワークフローが従来の両側各 1 セルの範囲（34〜51 フレーム）を使う場合は、長回し内の短い区間は全体が再生成されることがあります。
- **再生成範囲は映像だけをもとに決めています。** つなぎ目の音声は測定していません。範囲帯の一致の値が赤くなる境界（約 22 dB）は 2 つの実測点の間に置いたもので、校正していません。「これより低ければつながらない」という意味ではありません。
- **Fun ControlNet と FastH3 はパネルに組み込んでいません**。接続方法は上記を参照してください。
- **クリップ全体をリファインするボタンはありません。** 同じサイズで再生成しても改善はなく、拡大後の再生成は有効ですが、大きいサイズで新しく 1 本生成するのと同じ時間がかかります（[実測データ](#実測データ)を参照）。手動で行うには、完成クリップをソース動画にし、「ソース用途」を「ソース再描画」にして、「詳細設定」で変更量を 0.32（開始時のノイズ 85%）に設定し、大きいサイズのプリセットに切り替えて生成します。
- **顔のリファインの適用範囲は狭いものです。** ミディアム〜ロングショットの数十ピクセルの顔にだけ役立ちます（[実測データ](#実測データ)を参照）。所要時間は新たな生成とほぼ同じで、開始時のノイズに大きく左右されます。低すぎると変化せず、高すぎると顔の周りの背景も変わります。
- **顔のリファインは 1 ショットで 1 つの顔だけを処理します**（最も長く映っている顔）。人物を識別するわけではなく、「顔の参照対象」を選ぶと、処理するすべてのショットの顔をその人物の画像で描き直します。顔がショットの 4 割以上のフレームで検出されなければ処理しません（それ未満は誤検出が多いため）。検出器は動物や怪物の顔も顔と判定します。その場合は「対象ショット」で該当ショットを外してください。
- 1 ノードで 1 本のクリップを扱います（生成区間は 5〜15 秒）。長い内容は続きの生成でつなぎます。次のノードに動画を追加し、使い方を「動画の続き」にして、前のノードが保存したファイルを選びます。
- 出力ページは ComfyUI 自体の履歴を読み込みます。ComfyUI を再起動すると履歴が消え、一覧も空になります。ファイルは出力ディレクトリに残ります。
- ライブプレビューとプリセットの所要時間は、このブラウザーのページからキューに追加した実行だけを追跡します。別のブラウザーや API からの実行はここではプレビューせず、計測もしません。完成クリップは通常どおり保存し、通常の実行は出力ページに表示します。生成中にページを再読み込みしたりワークフローのタブを切り替えたりすると、少し後にプレビューが再開します（実測では十数秒以内）が、その実行の所要時間は記録しません。
- 検証した環境は 1 つだけです：Windows 11、VRAM 24 GB の GPU 1 枚。ほかの OS や、VRAM がより少ない GPU では確認していません。

## 開発とテスト

```bash
# ComfyUI のルートで、ComfyUI 付属の Python を使って実行
python custom_nodes/ComfyUI-GachaDirector/tests/test_grid.py
python custom_nodes/ComfyUI-GachaDirector/tests/test_schema.py
python custom_nodes/ComfyUI-GachaDirector/tests/test_widget_order.py
python custom_nodes/ComfyUI-GachaDirector/tests/test_expand.py
python custom_nodes/ComfyUI-GachaDirector/tests/test_splice.py
```

パネルはサーバーに問い合わせずにセル、画面サイズ、問題一覧を表示する必要があるため、ドキュメントのルールには JavaScript 側の対応実装があります。両者の一致は対照テストで確認します。そのほか、顔のリファインの追跡と切り出し・貼り戻し、複数テイクをつなぐ際のカット計画（`test_cuts.py`。上の `test_splice.py` は編集用ノードの映像・音声処理を検証）、実行中の生成がこのクリップのものかどうかの判定、素材とプロンプトの対応関係を検証します（最後の 3 コマンドは Node 20 以降が必要です。以下はノードパッケージのディレクトリで実行します）。

```bash
python tests/test_faces.py
python tests/test_cuts.py
python tests/make_parity_fixtures.py
node --experimental-default-type=module tests/parity.mjs
node --experimental-default-type=module tests/tracker.mjs
node --experimental-default-type=module tests/material.mjs
```

編集ページには実ブラウザーでのフローテストもあります（`@` の入力、キーボードによる名前選択、使い方の変更、名前変更、境界の挿入・結合、素材の削除、最終プロンプトの確認）。ヘッドレスの Edge または Chrome を使い、ComfyUI が実行中である必要があります。生成は行いません。

```bash
node --experimental-websocket tests/shot.mjs tests/ui_edit_flow.mjs --lang zh
```

サンプルワークフローは生成したものです：`python templates/make_workflows.py`。

`tests/measure_vae_cells.py` と `tests/measure_seam.py` はテストではなく、[実測データ](#実測データ)の数値を測るスクリプトです。前者は H3 の動画 VAE ファイルが必要で、CPU 上で実行します。後者は 3 本の動画ファイルだけで使えます。
